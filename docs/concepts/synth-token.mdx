Each market issues one SPL token. It is a completely standard SPL mint: it sits in associated token accounts, transfers freely, trades on [Meteora](https://www.meteora.ag) through Jupiter, and composes with any wallet or protocol that speaks SPL. What makes it track a collectible is not the token itself but the machinery around it: the oracle index, the funding tether, and its on-chain identity.

## Fixed supply, mint revoked

Every ***commas*** token is a **fixed-supply SPL token with a revoked mint authority**.

- The mint is created by the [Meteora](https://www.meteora.ag) DBC launch with a **fixed 1,000,000,000 supply**, no premint on top: the whole supply is the tradeable float in the pool. The mint is recorded on the market as `Market.synth_mint`; the program holds no mint authority over it.
- The mint authority is **revoked** at creation, so wallets and screeners show the mint as revoked from the first block. Nothing can ever mint again.
- Supply is fixed at 1B for the life of the market. There is no elastic, program-minted supply and no burn: tokens only move between accounts.
- Decimals: 6.

<Note>
This replaces the retired v1 model, where the program preminted around 1.6B tokens across an internal curve allocation, a hedge reserve, and an item reserve, then burned the unsold curve excess. The Meteora path is a clean **fixed 1B**, all of it tradeable.
</Note>

## Identity: the token is the collectible

The mint's on-chain Metaplex metadata points at commas' `/token-metadata` JSON, which carries the collectible's **name, image, and an "Underlying" / "Collectible ID" attribute set**. That is what makes Solscan and terminals render the token *as* the collectible, and it is how "the underlying is the collectible" shows up publicly. The identity is metadata plus oracle, not custody: the pool holds SOL and the token, not the physical item. See [What commas is not](/faq).

## Unit math

The scale constant for every market:

```text
1 unit = 1,000,000 tokens = 1e12 base units
```

The unit is **launch-scaled**: at launch, one unit's index is set equal to the token's launch price per unit, and the [Price Index](/concepts/price-index) moves it proportionally with the collectible from there. Since the index is quoted in lamports per whole unit:

```text
index_per_base_unit = index_lamports / 1e12
value(base_units)   = base_units * index_lamports / 1e12
```

Worked example: a market launches against a card and the index opens at some lamports-per-unit value `P`. If the card doubles, the pushed index doubles to `2P` per unit and one token (1e6 base units) is worth `2P * 1e6 / 1e12` lamports. The million-to-one split keeps the per-token price in memecoin territory; the launch scaling keeps premium and funding meaningful for every market regardless of how expensive the collectible is.

## Where circulating supply lives

The full 1B is minted into the [Meteora](https://www.meteora.ag) pool at launch and is the tradeable float from block one. There is no program-held reserve backing shorts, because shorts are [cash-settled](/concepts/shorts): they never draw or return tokens. The only program-held token account is the optional **item reserve**, funded by a plain SPL transfer at listing time:

| Path | Direction | When |
| --- | --- | --- |
| pool buy/sell (Meteora, via Jupiter) | pool ⇄ trader | Any time the pool is live |
| `deposit_item` | item reserve to depositor | Live, against a registered copy entering escrow |
| `withdraw_item` | holder back to item reserve | Live, taking a copy out of escrow |

Pool swaps move existing tokens between the Meteora pool and traders; item swaps move existing tokens between the item reserve and holders. Nothing in the system mints or burns, so supply is exactly 1,000,000,000 forever.

## Item swaps

A market's liquidity is not limited to SOL: the collectible has an **on-chain door in and out** of the market. When a market is backed by "Pikachu [PSA](https://www.psacard.com) 10", a holder of a vaulted copy of that card+grade can swap the real item for tokens, and any token holder can swap back for a copy while the item reserve holds one.

Both directions are **value-based**, priced at the oracle value, never a fixed per-item token count:

```text
gross tokens per item = index_twap * BASE_UNITS_PER_NFT * units_per_item_micro / mark_ema / 1e6
net    tokens per item = gross * (1 - 0.7%)
```

The index is launch-scaled (it prices a *unit*, not a card), so `units_per_item_micro` restores the item's real size: how many units one physical item was worth at launch, in millionths. The numerator is what one copy is worth at the current oracle value and the denominator is what one token trades for (the mark EMA), so you exchange one item for tokens of equal value at that moment, minus the **0.7%** swap fee:

- Token trading at parity to its index: one copy swaps for about `units_per_item` units of tokens, less the fee.
- Token trading at half the index: one copy swaps for about twice that, because each token is worth half as much. The value received is the same, less the fee.

Mechanics:

- Only **registered** copies are accepted. [`register_item`](/reference/instructions#register_item) creates an `ItemRegistration` PDA per (market, item mint); registration is admin-gated in v1 while the relayer verifies vault provenance off chain.
- Deposited copies sit in a market-authority escrow (one ATA per item mint); `Market.items_deposited` counts them and `ItemSwapped` fires on every swap. See [Events](/reference/events#itemswapped).
- Deposit tokens come from the **item reserve** (`["items", market]`), funded by an SPL transfer at listing. `ItemReserveDepleted` bounds the facility; withdrawals refill the reserve. A market with a zero item reserve has no item facility.
- The swap fee is the same **0.7%** the pool charges, split 50/50 creator/protocol.

**Why the mark EMA and not spot.** Pricing the swap off the live pool spot would make it sandwichable: buy the pool up, swap a copy into the inflated price, dump. The mark EMA moves by at most `min(dt, window)/window` per block, so a single-transaction price spike barely moves the swap rate. The same smoothing that protects [funding](/concepts/funding) protects item swaps.

**What this does to the market.** The swap is deliberately value-based: at execution you give and receive equal value (less the fee), so it is not itself an arbitrage against the pool. What it adds is a physical entry and exit. A holder converts a copy into liquid tokens at fair value without a marketplace sale, and while the item reserve and escrow hold copies, any token holder can convert index-referenced exposure into the real thing. This is **optional redemption**, not custody by default: the token is price exposure; the item swap is the door for anyone who actually wants the physical item.

## The tether, briefly

The token has no fixed-rate redemption pot, and [item swaps](#item-swaps) are optional value exchanges rather than a peg mechanism. What holds the pool price near the index is the [funding](/concepts/funding) rate and the [cash-settled shorts](/concepts/shorts) that respond to it: when the token trades rich, funding pays shorts and hedgers open shorts against the mark; when it trades cheap, funding charges shorts and they close. See [How it works](/how-it-works#the-tether).
