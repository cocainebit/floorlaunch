title: "Parameters"

Every market carries a full `MarketParams` struct. Defaults live on the `Global` account and are set at `init_global`; the admin may override them per market at creation, and update them later with [`update_market_params`](/reference/instructions#update_market_params).

<Note>
The values below are illustrative, chosen to show sensible orders of magnitude for a liquid mainnet market. They are not final and would be tuned per underlying at listing time. The trade fee itself is the [Meteora](https://www.meteora.ag) pool base fee (0.7%), set by the pool config, not a commas parameter.
</Note>

## Oracle and index

| Field | Type | Meaning | Illustrative |
| --- | --- | --- | --- |
| `index_window_secs` | u32 | EMA window for the index TWAP; a push moves the TWAP by min(dt, window)/window | 21600 (6h) |
| `min_push_interval_secs` | u32 | Minimum seconds between accepted oracle pushes | 1800 (30m) |
| `breaker_bps` | u16 | Push deviation from TWAP that trips the [circuit breaker](/concepts/circuit-breaker) | 2000 (20%) |
| `max_index_age_secs` | u32 | [Staleness guard](/concepts/price-index#staleness-guard): an index older than this blocks shorts, withdrawals, closes, funding, and liquidations (`IndexStale`); 0 disables | 14400 (4h) |

## Mark price and funding

| Field | Type | Meaning | Illustrative |
| --- | --- | --- | --- |
| `mark_window_secs` | u32 | EMA window for the oracle-pushed Meteora mark used by funding | 3600 (1h) |
| `funding_k_bps` | u16 | Funding sensitivity; 10000 = daily rate equals the premium | 5000 (0.5x) |
| `max_funding_bps_per_day` | u16 | Absolute clamp on the daily funding rate | 300 (3%/day) |
| `min_crank_interval_secs` | u32 | Minimum seconds between `accrue_funding` cranks | 300 (5m) |

## Collateral and liquidation

| Field | Type | Meaning | Illustrative |
| --- | --- | --- | --- |
| `initial_cr_bps` | u16 | Collateral ratio required to open a short or withdraw collateral | 15000 (150%) |
| `maintenance_cr_bps` | u16 | CR below which a position is liquidatable | 12000 (120%) |
| `liq_bonus_bps` | u16 | Liquidator premium over the settled loss | 500 (5%) |
| `max_open_interest` | u64 | Cap on total short open interest (notional), in token base units. No supply is preminted for it: shorts are [cash-settled](/concepts/shorts), so this bounds notional exposure, not a token reserve | sized to underlying depth |

`max_open_interest` is the tail-wags-dog guard: it keeps the synthetic market from outgrowing the real collectible market whose price it references. Sizing it is a listing-time judgment call; see [Listing a Market](/guides/listing-a-market). Because the short side settles against the [insurance fund](/concepts/insurance-fund), a market's practical short capacity is the smaller of this cap and what the fund can back. `update_market_params` can raise or lower the cap; the fund is topped up permissionlessly with `fund_insurance`.

## Item swaps

| Field | Type | Meaning | Illustrative |
| --- | --- | --- | --- |
| `item_reserve` | u64 | Token allocation backing [item swaps](/concepts/synth-token#item-swaps), base units, funded by an SPL transfer at listing; 0 disables the facility | sized for the copies you expect deposited at once |
| `units_per_item_micro` | u64 | How many units (1M tokens each) one physical item was worth at launch, in millionths: `index_at_launch / launch_price_per_unit`. Carries the item's real size into item swaps, since the launch-scaled index prices a unit, not a card. Must be `> 0` whenever `item_reserve > 0` (`ZeroAmount` otherwise) | `1_000_000` = one unit per item |

The item reserve is funded by a plain SPL transfer at listing (the mint is external and fixed at 1B). Each `deposit_item` pays roughly `index_twap * 1e12 * units_per_item_micro / mark_ema / 1e6` base units out of it, less the **0.7%** swap fee, and each `withdraw_item` returns the same formula's worth, so the reserve floats around its funded size as copies flow in and out. Size it to the number of registered copies you realistically expect deposited at once, with headroom for the token trading below parity (a cheap mark pays out more tokens per copy).

## Launch venue (Meteora)

The retired v1 internal-venue parameters (`curve_virtual_sol`, `curve_virtual_tokens`, `curve_fee_bps`, `graduation_target_sol`, `insurance_share_bps`, `amm_fee_bps`) no longer apply: the token launches on a [Meteora](https://www.meteora.ag) DBC pool and migrates to DAMM v2, so the curve schedule, migration, and trade fee are Meteora's, not commas'. The trade and item-swap fee is the pool's **0.7%** base fee, split 50/50 creator/protocol. The insurance fund is seeded permissionlessly with `fund_insurance` rather than from a launch raise. See [Launch Venue](/concepts/launch-curve) and [Insurance Fund](/concepts/insurance-fund).

## How parameters interact

A few couplings worth knowing when tuning:

- **Breaker vs push interval.** `breaker_bps` bounds movement per accepted push, and `min_push_interval_secs` bounds push frequency, so together they cap the index's maximum slew rate even under a compromised oracle key.
- **Staleness vs push cadence.** `max_index_age_secs` should comfortably exceed the relayer's push interval (and `min_push_interval_secs`), or routine gaps will lock short operations; a 4h guard against an hourly push cadence leaves room for a few missed cycles.
- **Initial vs maintenance CR.** The gap (150% vs 120% illustrative) is the shorter's buffer: how much the index can rise before a fresh position at minimum collateral becomes liquidatable.
- **Funding clamp vs open interest.** Worst-case daily value transfer from a manipulated index is `max_open_interest * max_funding_bps_per_day / 10000`. These two parameters, together with the insurance fund's balance, are the security budget.
