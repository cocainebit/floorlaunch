description: "Every token launches as a Meteora Dynamic Bonding Curve pool and migrates to DAMM v2. This replaces the retired internal commas bonding curve."
---

Every market launches on a **[Meteora](https://www.meteora.ag) Dynamic Bonding Curve (DBC)** pool. This is the launchpad phase: anyone can buy the token with SOL through Jupiter from the first block, price rises deterministically along Meteora's curve, and as the curve fills Meteora **migrates the pool to DAMM v2**. commas never holds the curve or the pool; it attaches the synthetic layer (oracle index, funding, cash-settled shorts, item swaps) alongside.

<Note>
This replaces the retired v1 venue. The old internal commas bonding curve ran a self-contained constant-product curve and AMM inside the program, with a preminted allocation and a graduation gate at a fixed SOL target. That venue is superseded by the Meteora DBC path documented here, so the token trades on audited, Jupiter-routed infrastructure and is visible on Axiom, Photon, Solscan, and Jupiter from launch.
</Note>

## The mint

The DBC launch creates a fresh SPL mint with a **fixed 1,000,000,000 supply** and **revokes the mint authority**. The whole supply is the tradeable float in the pool; there is no premint on top. commas records the mint as `Market.synth_mint` and sets its [Metaplex metadata](/concepts/synth-token#identity) so it renders as the collectible. See [The Token](/concepts/synth-token).

## Buying and selling

Buys and sells route through **Jupiter** into the Meteora pool, the same as any Solana token. The pool charges a **0.7%** base fee, split 50/50 creator/protocol (the creator half can route to an [identity escrow](/reference/pdas#identity-escrows)). Price is set by Meteora's DBC math during the bonding phase and by the DAMM v2 constant-product pool after migration; commas does not re-implement the curve.

The collectible enters only through the **oracle index**, which is launch-scaled: at launch one unit's index is set equal to the token's launch price per unit, and the [Price Index](/concepts/price-index) moves it proportionally with the collectible from there. That keeps premium and [funding](/concepts/funding) meaningful without commas touching the pool price.

## The mark

commas does not parse Meteora's pool bytes on chain. The relayer computes the pool price from Meteora's public API and pushes it as the **mark** via [`push_mark`](/reference/instructions#push_mark); it lands in the same `mark_ema` smoothing that [funding](/concepts/funding) reads. The mark only steers funding; it never enters collateral or liquidation math, which always use the oracle index. See [AMM & Mark Price](/concepts/amm).

## Migration to DAMM v2

Migration from the DBC to a **DAMM v2** pool is Meteora's, on Meteora's schedule, not a commas graduation gate. No commas instruction has to be cranked for the token to keep trading, and the oracle market, funding clock, and hedging facility run across both phases without interruption. See [Migration](/concepts/graduation).

- Attach instruction: [`create_external_market`](/reference/instructions#create_external_market), see [Instructions](/reference/instructions)
- Mark push: [`push_mark`](/reference/instructions#push_mark)
- Parameters: fee and risk parameters carry over from listing; the pool schedule is Meteora's, see [Parameters](/concepts/parameters)
